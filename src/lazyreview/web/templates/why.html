Why lazyreview?

lazyreview is a local, human-in-the-loop desk for agentic pull-request review. It finds the PRs waiting on you, orients with an analysis brief, runs several review agents in parallel, consolidates them into one consensus, drafts the GitHub-facing comment — and stops. Nothing posts until you say so.

What it does today

  • Discovers review-requested PRs via gh and keeps a local SQLite history of runs, costs, and feedback.
  • Gates on PR analysis — an orientation brief for the current head must succeed before reviews or consolidations can start.
  • Batch multi-agent reviews (Claude, Agy, Cursor) with your default models and effort from Settings.
  • Consolidates into one report with a recommended GitHub action (approve, request_changes, or comment).
  • Publish transform turns the internal report into a GitHub draft you can edit, then submit yourself.
  • Interactive chat — Explore a PR (worktree Q&A) or Challenge a consolidation (evolve findings + recommended action). Right-rail chat, sandboxed to that PR only; Done regenerates the publish draft. Never auto-posts to GitHub.
  • Head-aware — when the PR moves, stale runs and reports are flagged so you don’t post yesterday’s review.

Workflow

After the analysis brief, you kick off one or more agentic reviews. Those runs feed a single consolidate-and-publish step; you iterate on that draft until it is ready, then post to GitHub yourself.

Local architecture

Everything durable stays on your machine. Sync and post talk to GitHub through gh; analysis and every review share one detached worktree per PR (backed by a bare mirror). Findings and the analysis brief are written into SQLite. Consolidate / publish / human challenge reuse that stored context in a consolidation job directory — they do not need a second checkout.

  • One worktree per PR — created lazily, held while analysis or review jobs run, reused across agents for the same head.
  • SQLite is the handoff — consolidate does not re-read the worktree; it loads the brief and findings from the DB into consolidations/{id}/.
  • Human challenges stay local — edit or regenerate the draft against that consolidation dir + DB until you post.

Prompt chaining

Each stage has its own prompt. Analysis, consolidator, and publish prompts are editable under Settings; review runs use the review skill. Outputs of earlier stages become inputs to later ones — not a single mega-prompt.

  1. Analysis — orientation brief for the current head (intent, coverage, blast radius).
  2. Reviews — independent agentic passes; findings stored per run.
  3. Consolidate — dedupe across runs and existing PR comments; emit an internal report plus meta.json.
  4. Publish — rewrite that report into concise GitHub-facing markdown (still local).
  5. Submit — you choose the action, edit the draft, and post. Never auto-posted.

Not another auto-review bot

Generic AI PR bots drop comments straight onto GitHub. lazyreview is the opposite: multi-agent signal in, one consensus out, human still owns the write. Worktrees, logs, and history stay on your machine. When the head moves, stale work is marked so you don’t ship a review for the wrong commit.

Why the name?

A nod to lazygit, lazyvim, and lazydocker — tools that take a tedious everyday workflow and make it feel light without stripping away power. Same spirit, applied to code review with AI agents: less ceremony in the loop, more time actually reading the diff.

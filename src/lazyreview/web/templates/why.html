Why lazyreview?

lazyreview is a local, human-in-the-loop desk for agentic pull-request review. It finds the PRs waiting on you, orients with an analysis brief, runs several review agents in parallel, consolidates them into one consensus, verifies those findings against the PR worktree, drafts the GitHub-facing comment — and stops. Nothing posts until you say so.

What it does today

  • Discovers review-requested PRs via gh and keeps a local SQLite history of runs, costs, and feedback.
  • Gates on PR analysis — an orientation brief for the current head must succeed before reviews or consolidations can start.
  • Batch multi-agent reviews (Claude, Cursor, Agy, Codex) with your default models and effort from Settings.
  • Consolidates into one report — dedupes across runs and existing PR feedback into an internal consensus plus meta.json.
  • Verifies findings against the worktree — reproduces or refutes each consensus claim, drops false alarms, and recomputes the recommended GitHub action (approve, request_changes, or comment).
  • Publish transform turns the verified internal report into a GitHub draft you can edit, then submit yourself.
  • Interactive chat — Explore a PR (worktree Q&A) or Challenge a consolidation (evolve findings, recommended action, report tone, and publish guidance). Right-rail chat, sandboxed to that PR only; Done regenerates the publish draft. Never auto-posts to GitHub.
  • Chat safety — hard preflight blocks host recon, secret/env extraction, jailbreaks, and clear off-topic asks before an agent runs; prompts use an allowlist + refuse template; tools stay in the PR worktree; replies redact credential-shaped tokens and foreign home paths. Defense in depth for trusted local use — not multi-tenant ACLs.
  • Head-aware — when the PR moves, stale runs and reports are flagged so you don’t post yesterday’s review.

Workflow

After the analysis brief, you kick off one or more agentic reviews. Those runs feed consolidate → verify findings against the PR worktree → publish draft; you iterate on that draft until it is ready, then post to GitHub yourself.

Local architecture

Everything durable stays on your machine. Sync and post talk to GitHub through gh. Analysis, reviews, verify, and interactive chat share one detached worktree per PR (backed by a bare mirror). Findings and the analysis brief land in SQLite. Consolidate and publish run in a consolidation job directory staged from the DB; verify holds the shared worktree and rewrites those consensus artifacts before the publish transform.

  • One worktree per PR — created lazily, held while analysis, review, verify, or interactive chat runs, reused across agents for the same head.
  • SQLite is the handoff into consolidate — brief and per-run findings are staged into consolidations/{id}/ (no worktree for that merge pass).
  • Verify uses the worktree — after consolidate, a separate agent pass holds the shared PR worktree, reproduces or refutes each consensus finding, and rewrites the consensus artifacts before publish.
  • Human challenges stay local — edit, chat, or regenerate the draft against that consolidation dir + DB until you post.
  • Chat stays on the PR — messages that ask for host paths, secrets, system prompts, jailbreaks, or clear off-topic questions are refused in the UI without spawning an agent; allowed rounds run in the shared worktree with tool allowlists and reply redaction.

Prompt chaining

Each stage has its own prompt. Analysis, consolidator, verify, and publish prompts are editable under Settings; review runs use the review skill. Outputs of earlier stages become inputs to later ones — not a single mega-prompt.

  1. Analysis — orientation brief for the current head (intent, coverage, blast radius).
  2. Reviews — independent agentic passes; findings stored per run.
  3. Consolidate — dedupe across runs and existing PR comments; emit an internal report plus meta.json.
  4. Verify — reproduce or refute each consensus finding in the shared PR worktree; drop false alarms; recompute recommended_action.
  5. Publish — rewrite the verified report into concise GitHub-facing markdown (still local).
  6. Chat (optional) — Explore the PR worktree, or Challenge findings / recommended action / draft tone (hard preflight + sandbox + reply redaction); Done regenerates the publish draft.
  7. Submit — you choose the action, edit the draft, and post. Never auto-posted.

Not another auto-review bot

Generic AI PR bots drop comments straight onto GitHub. lazyreview is the opposite: multi-agent signal in, verified consensus out, human still owns the write. Worktrees, logs, and history stay on your machine. When the head moves, stale work is marked so you don’t ship a review for the wrong commit.

Why the name?

A nod to lazygit, lazyvim, and lazydocker — tools that take a tedious everyday workflow and make it feel light without stripping away power. Same spirit, applied to code review with AI agents: less ceremony in the loop, more time actually reading the diff.
